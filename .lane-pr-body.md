## Show which feature a conversion is on

While a design's history is built, the command line and the desktop app now name the feature
it is on, and say when SolidCraft is checking that feature by measurement.

- CLI (terminal line, `--verbose`): `Building history for Bracket: 3 s; Feature 29 of 37 · Extrude 1; 1 of 1 designs read; 12 s elapsed`,
  with ` (checking by measurement, which takes longer)` after the feature while SolidCraft measures it.
- Desktop card: a `Feature 29 of 37 · Extrude 1` line under the running step, and while the
  feature is measured, a small note: "Checking this feature by measurement in SolidCraft.
  Features checked by measurement take longer."
- Folder runs: the running-file line under the counts gains the same feature line.

## How it works

- `dutchman-core` `Progress` gains `features(total)` (a guard per timeline, per worker thread)
  with `at(index, name)`, and `measuring()` (a guard that marks the worker's current feature as
  measured). The running step of a worker carries that worker's feature, so assembly workers
  never show each other's features.
- Feature changes alone emit at most four events a second; a change that was not emitted at
  once is flushed by the existing heartbeat thread, which now wakes every 250 ms (heartbeats
  stay at five seconds). Measuring starts and ends emit at once.
- History mapping (`history::map_with_profile_check`) reports each timeline row as it reaches
  it; `profile_check` (the replay that admits an inferred profile against the source's
  bodies) holds `measuring()` while it runs. Measured inference will use the same guard.
- The whole-design check after mapping, blend proofs and the retained-prefix check run once
  per design, so they keep showing their own check line, not a feature.

## Report

`dutchman.progress/1` gains an optional `running.feature` object (`index`, `total`, `name`,
`measured`), documented in docs/json.md. Fields are only added; older workers omit it and the
parser accepts that. Names stay private local text, like `running.name`: diagnostics logs and
anonymous reports never record them. Final reports do not change.

## Measurements

Release builds of main (41616cee) and this branch on aurora, `convert-all --no-verify --json --jobs 1`,
alternating order, while aurora carried other jobs (load about 40), so single runs are noisy. Durations are the gaps between successive runs' report file times (the job's own timing table was lost when it hit its time limit):

| Set | Features mapped | main runs (s) | branch runs (s) | Best main / branch |
|---|---|---|---|---|
| Public 50 Fusion files | 2,358 (largest design 1,498) | 418, 346 | 638 (first, cold), 340 | 346 / 340 |
| RailCore, 3 `.f3z` | 1,475 (largest 529) | 199 (first, cold), 153, 148 | 284, 145 | 148 / 145 |

These noisy shared-worker runs do not establish a performance difference. Final JSON reports are the same as main's apart from the output
path. Progress lines grew from about 3,150 to 3,700-3,775 (public 50) and from 2,117 to
2,446-2,481 (RailCore): 713 and 433 lines carried a feature for 2,358 and 1,475 features,
so the four-a-second limit holds and a fast timeline does not print a line per feature.
`--no-verify` runs measure nothing in SolidCraft, so `measured` stays false there.
